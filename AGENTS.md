# Інструкції для AI-асистента

## Проєкт
- Відповідай українською. Власний код UA Address Search має ліцензію MIT.
- Перед роботою з кодом звіряйся зі STRUCTURE.md; великі файли читай точково через rg.
- Плагін: ua_address_search/. Сервер: server/. Дослідження: research/.
- Сумісність QGIS 3.28–4.99, Qt5/Qt6, Python 3.9+ у плагіні; сервер Python 3.12.
- Використовуй qgis.PyQt, мережеві засоби QGIS, зрозумілі назви й PEP 8.
- Не змінюй архітектуру й сторонні файли без потреби. Коментуй неочевидну логіку.

## Версії та релізи
- Кожна завершена ітерація змін робочого коду інкрементує четверту цифру версії
  в ua_address_search/metadata.txt; оновлюй CHANGELOG.md та dist/plugins.xml.
- Після змін плагіна запускай python -B scripts/package_plugin.py та
  python -B scripts/sync_to_profiles.py. ZIP містить MIT LICENSE, не містить
  секретів, кешів, тестів або файлів, виключених .gitignore.
- Перед комітом робочого коду запускай модульні та доступні QGIS smoke-тести.
- Не перезаписуй копії запущеного QGIS без --allow-running-qgis.
  Коли користувач прямо просить синхронізувати профілі, цей прапорець дозволений.
- ZIP та plugins.xml у dist/ версіонуються. Remote, push, публікація та
  розгортання Railway виконуються лише за окремим запитом.

## Швидкі команди
- «Перепакуй плагін»: package_plugin.py, sync_to_profiles.py; без тестів і bump.
- «Онови у QGIS»: sync_to_profiles.py --allow-running-qgis; без тестів і bump.
- «Протестуй»: python -B scripts/smoke_test_all_qgis.py; без пакування і bump.
- «Підніми білд»: четверта цифра metadata.txt та dist/plugins.xml.

## Безпека і сервер
- Спільний ключ Visicom зберігається в .env розробника або серверних секретах;
  власний ключ користувача — лише в QGIS Authentication Manager для прямих запитів.
- Не виводь ключі, токени, Authorization або upstream URL у логи чи відповіді.
- Персональні токени зберігай як хеші; у QGIS — через Authentication Manager.
- Квоти резервуй транзакційно до upstream-запиту; не повторюй його автоматично.
- Один екземпляр сервера, SQLite на постійному томі; доба Europe/Kyiv.
- Звичайні тести не використовують Visicom. Live-перевірки — лише окремою
  командою з явним лімітом кількості запитів.

## Тести та документація
- Змінена поведінка потребує відповідних тестів і документації.
- Перевіряй Feature/FeatureCollection, CRS, скасування, квоти, помилки й
  initGui/unload/reopen без дублікатів. Ізолюй ресурси й налаштування тестів.
- При зміні структури оновлюй STRUCTURE.md.
- Plan/Ask: не редагуй код. Для плану пропонуй варіанти й очікуй вибору.

## Git
- main — основна; development — робоча гілка.
- Коміть завершені ітерації в робочій гілці, додавай версію до назви коміту.
- Стадіюй конкретні файли задачі; не додавай .env і сторонні зміни.
