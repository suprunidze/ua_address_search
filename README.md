# Visicom Data API for QGIS

Українськомовний плагін **QGIS 3.28–4.99** із вкладками Адреси, Об’єкти, Маршрут,
Матриця відстаней, Оптимізація та Прив’язка до доріг, адресним Locator і вісьмома
алгоритмами Processing. Буфер і побудова точки за азимутом не включені.
Власний код плагіна — **MIT**. Текст ліцензії входить до ZIP.

Папка пакета — `visicom_data_api`, архів — `dist/visicom_data_api.zip`.
Попередні налаштування не мігруються. Для одноразового встановлення замість старого
плагіна закрийте QGIS і виконайте `python -B scripts/sync_to_profiles.py --remove-old-plugin`.
Старі копії переносяться за межі каталогу plugins у `python/visicom_plugin_backups`.

Квота, Налаштування й Довідка спільні для всіх вкладок. Перемикання скасовує
незавершені запити та вибір на карті, зберігаючи параметри й готові результати.
На нових вкладках результати видно в таблиці, геометрію — на карті; кнопка додавання
створює шари проєкту, розділені за типом геометрії. Для категорій можна ввести коди
з офіційного довідника Visicom через кому.

**Processing завжди потребує власного ключа**, навіть коли панель працює через Railway.
Щоб зберегти його, виберіть власний ключ у налаштуваннях; після збереження можна
повернути режим панелі на Railway. Ключа немає серед параметрів чи в історії алгоритму.
Алгоритми: геокодування поля таблиці, зворотне геокодування точок, пошук об’єктів,
отримання за полем ID, маршрут, матриця, оптимізація та прив’язка.
Виходи POINTS/LINES/POLYGONS/TABLE підтримують тимчасові та файлові результати;
STATUS має значення completed, partial_canceled або partial_error.

Ліміти: маршрут 27 точок разом зі стартом і фінішем; матриця 25 × 25;
TSP 50; прив’язка та отримання за ID 250; пошук до 250 результатів.
Автоматичного розбиття немає. Довжини — метри, час у дорозі не розраховується.
TSP повертає порядок відвідування; дорожню лінію можна побудувати окремим запитом
лише в межах ліміту маршруту. Перша/остання точки фіксуються за правилами TSP.
Для маршруту, оптимізації та треку виберіть унікальне поле порядку; усі геометрії
повинні мати відомий CRS. Недоступна пара матриці має статус і порожню відстань.

Серверний код нових операцій підготовлений локально. Через Railway ці операції
запрацюють після окремого розгортання; власний ключ звертається безпосередньо до Visicom.
Дані Visicom і сторонні компоненти зберігають власні умови та атрибуцію.

## Встановлення та використання

1. У QGIS: «Модулі → Керування та встановлення модулів → Встановити з ZIP»;
   виберіть `dist/visicom_data_api.zip` і ввімкніть Visicom Data API for QGIS.
2. У «Налаштуваннях» виберіть спільний доступ Railway або власний ключ Visicom.
   Railway автоматично реєструє інсталяцію при першому запиті; вводити токен не потрібно.
   У прямому режимі введіть власний ключ: запити йдуть до Visicom без Railway.
3. Задайте головний пароль QGIS Authentication Manager, якщо QGIS його запитає.
   У QgsSettings зберігається ідентифікатор конфігурації, не секрет.
4. Введіть адресу та натисніть Enter/«Знайти». Перший результат вибирається автоматично;
   точка підсвічується з flash. Вибір іншого результату переміщує карту до нього.
   Або використовуйте Locator: `адр Київ, Хрещатик, 26`.
5. Чекбокс «Автоматично отримувати геометрію» увімкнений за замовчуванням і зберігається.
   Він керує отриманням повної геометрії для вибраного результату панелі, кліку й Locator.
   Вимкнення залишає точку; увімкнення одразу показує геометрію поточного результату.
   Перше отримання `/feature` витрачає окремий запит; повтори використовують кеш.
   Іконка «Завантажити геометрію» додає об’єкт до тимчасового шару без дублікатів ID,
   незалежно від чекбокса. Під час набору тексту Locator геометрію не отримує.
6. Адресу вибраного результату можна копіювати іконкою, контекстним меню або Ctrl+C
   у списку. Після «Налаштування» є іконка «Допомога»: вона відкриває локальну
   українську HTML-довідку в системному браузері, без мережевих ресурсів.

Перший ряд панелі: toggle найближчої адреси, поле адреси, «Знайти», «Скасувати».
Рядок стану — під списком над чекбоксом геометрії. Завантаження й налаштування
мають підписи з іконками; текст квоти розміщений унизу. Ширина налаштувань — від
500 логічних px, висота підлаштовується під поля й шрифт; ручне розтягування вимкнене.

Завантаження геометрії зберігає поточну рамку, масштаб, центр і CRS карти — також
якщо користувач перемістив карту під час очікування або це перший шар проєкту.
Вибір іншого результату пошуку, як і раніше, переміщує карту до нього.

Режим кліків залишається ввімкненим для послідовного пошуку найближчих адрес у 50 м.
Повторне натискання toggle або інший інструмент QGIS вимикають режим.
«Скасувати» зупиняє запити й негайно прибирає хрестик, лінії, полігони та flash
пошуку, також після завершення запиту. Результати, кеш, завантажені шари й накладки
інших плагінів зберігаються. Запізніла відповідь після скасування не повертає підсвічування.

Залишок квоти відображається текстом і оновлюється після запитів із відповідей API;
окремого запиту після кожного пошуку немає. Кешовані повтори не витрачають квоту.
Наявний персональний токен Railway зберігається; повторної реєстрації не потрібно.

При вичерпанні добової квоти спільного доступу плагін показує немодальне вікно
з посиланням на реєстрацію Visicom і кнопкою переходу до налаштувань власного ключа.
Вид ліміту не деталізується. Автоматичний показ — один раз за добу для поточного
доступу протягом сесії; хвилинні обмеження й помилки власного ключа залишаються статусом.
Перехід у налаштування не зберігає новий режим до натискання «Зберегти».

Для власного ключа доступна опція показу добової квоти (типово 1500). Це **локальна
оцінка** лише цього плагіна на комп’ютері, спільна для його профілів QGIS3/QGIS4.
SQLite зберігається в `QStandardPaths.GenericDataLocation/VisicomDataApi/usage.sqlite3`;
ключа в ній немає. Рахуються спроби фактичного відправлення, включно з помилками
й геометрією; інші програми та комп’ютери не враховуються. Перевищення попереджає,
але не блокує запити. Якщо опцію вимкнено, видно кількість виконаних запитів.
Перемикання провайдера скасовує задачі й очищає кеш; секрети режимів зберігаються окремо.

Префікс `адр` має три символи: коротші префікси QGIS резервує для вбудованих фільтрів.

HTTP дозволено лише на localhost для розробки. Зміна сервера вимагає повторно
ввести токен. Для Locator розблокування сховища відбувається при явному пошуку.
Плагін використовує поточну карту й CRS, не додає підкладку. Геометрія за кнопкою
завантажується у тимчасові шари EPSG:4326 окремо для точок, ліній та полігонів.
При вимкненні режиму кліків відновлюється попередній інструмент карти, якщо він ще існує.
Якщо сторонній плагін уже видалив його C++-об’єкт, адресний інструмент вимикається
без переривання пошуку. Інструмент, самостійно вибраний користувачем, не перемикається.
Пакетна обробка й експорт не входять до цієї версії.

## Кеш робочої сесії

Панель і Locator використовують спільний кеш у RAM (128 МіБ, LRU, без TTL).
Кешуються пошук, порожні результати, точний зворотний пошук і геометрія за ID.
Регістр і зайві пробіли пошуку не створюють нових запитів; пунктуація та номери
будинків зберігаються. Одночасні однакові запити об’єднуються в один.
Помилки не кешуються; квота зберігається окремо від результатів і надходить із відповідями.

Кеш переживає закриття панелі й зміну проєкту, але очищається при зміні сервера,
токена або вивантаженні плагіна. Після витіснення LRU-запису можливий новий запит.
Позначка «З кешу сесії» та журнал QGIS показують локальне повторне використання.
Locator шукає лише з префіксом, після 1000 мс паузи та мінімум трьох символів.

## Локальний сервер (PowerShell, із кореня репозиторію)

Рекомендоване середовище сервера — Python 3.12. Плагін не потребує pip-залежностей.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -B -m server.app.tokens issue --label pilot --output artifacts/pilot.secret
.\.venv\Scripts\python.exe -B -m server.app.run --env-file .env
```

`.env` містить `VISICOM_DATA_API_KEY`; інші параметри наведені у `.env.example`.
За замовчуванням сервер слухає `http://127.0.0.1:8000`, SQLite —
`artifacts/uaas.sqlite3`. Токен видається в ігнорований файл `.secret`, а не в лог;
передайте його користувачу приватним каналом. У Windows захистіть доступ до файлу
засобами ACL. Видаліть приватний файл після передачі, якщо він більше не потрібен.

Відкликання всіх токенів із заданою міткою:

```powershell
.\.venv\Scripts\python.exe -B -m server.app.tokens revoke --label pilot
```

CLI і сервер повинні використовувати той самий `UAAS_DB_PATH`.
Для нестандартного шляху задайте цю змінну також у середовищі CLI.

## API та квоти

Робочі маршрути вимагають `Authorization: Bearer <personal-token>`:

| Метод | Маршрут | Вхід |
|---|---|---|
| POST | `/v1/search` | `{"text":"Київ, Хрещатик, 26"}` |
| POST | `/v1/register` | `{"installation_id":"UUID"}`, Bearer-секрет інсталяції |
| POST | `/v1/reverse` | `{"longitude":30.5234,"latitude":50.4501}` |
| GET | `/v1/features/{id}` | Ідентифікатор із результату пошуку |
| GET | `/v1/quota` | Без параметрів |
| GET | `/healthz` | Без токена, без upstream-запиту |

Пошук і геометрія повертають `{"results":[...],"quota":{...}}`; поля результату: `id`, `label`,
`address`, `category`, `center`, `bbox`, `attribution`, `geometry`.
`center` — `[longitude, latitude]`, `bbox` — `[west, south, east, north]`, WGS84.
Помилки: `{"error":{"code":"daily_quota"}}`; квоти — HTTP 429,
неправильний токен — 401, введення — 422, upstream — 502/503/504.
`/healthz` підтверджує роботу процесу, а не доступність Visicom.

Авторизовані оброблені помилки також містять `quota`. Знімок має `day`, `timezone`,
`remaining`, `token_daily_limit` та `observed_at` (Unix nanoseconds); клієнт відкидає
старіші знімки. Додаткові поля сумісні зі старими клієнтами, `/v1/quota` зберігається.

Перед реєстрацією клієнт зберігає UUID у QgsSettings, а випадковий секрет —
у QGIS Authentication Manager.
`/v1/register` ідемпотентний для цієї пари, повертає `registered: true` та `quota`,
не витрачає квоту Visicom. Інший секрет для того самого UUID дає 409; відкликаний
доступ — 403 і не відновлюється автоматично. Реєстрація представляє інсталяцію,
не підтверджену особу. Відкликання: CLI з міткою `installation-<UUID>`.
Нові реєстрації обмежені транзакційно до 10/хвилину та 100/добу загалом;
`UAAS_REGISTRATION_MINUTE_LIMIT`, `UAAS_REGISTRATION_DAILY_LIMIT` змінюють межі,
`UAAS_REGISTRATION_ENABLED=false` забороняє нові реєстрації. Повтор чинної пари
дозволений і не витрачає ці ліміти. Лічильники переживають перезапуск.

Типові межі: 1500 upstream-запитів/добу загалом, 100 на токен, 10 клієнтських
запитів/хвилину на токен. `/v1/quota` враховується лише у хвилинному ліміті.
Для конкретного токена адміністратор може задати `UAAS_TOKEN_DAILY_LIMIT_OVERRIDES`:
JSON-об’єкт `{SHA256_токена: додатний_добовий_ліміт}`. Хеші та значення токенів
не публікуйте; передавайте змінну через stdin або секретні параметри Railway.
Налаштування не змінює БД, типовий ліміт інших токенів або поточні лічильники.

Кожний upstream-запит резервує бюджет перед відправленням; помилки й скасування
не повертають резерв, автоматичних повторів немає. Межа доби — Europe/Kyiv.
Звернення інших програм із тим самим ключем сервер не бачить.

## Railway: розгортання

- Build context / Root Directory — корінь репозиторію (`/`). Поточний Railway
  відхиляє Config as Code через `railwayConfigFile`, тому налаштування сервісу
  задаються безпосередньо. `server/railway.toml` залишено як legacy-опис.
- Builder — Dockerfile, шлях `server/Dockerfile`; додатково можна задати
  `RAILWAY_DOCKERFILE_PATH=server/Dockerfile`. Healthcheck — `/healthz`, timeout 30 с,
  restart — ON_FAILURE, максимум 3 повтори.
- Dockerfile — `server/Dockerfile`; один процес Uvicorn і один екземпляр сервісу.
- Приєднайте постійний Volume у `/data`, задайте `UAAS_DB_PATH=/data/uaas.sqlite3`.
- `VISICOM_DATA_API_KEY` додайте як серверну секретну змінну, не через Git.
- Для прав доступу до Railway Volume задайте `RAILWAY_RUN_UID=0`, `PORT=8000`;
  публічний домен має спрямовуватися на порт 8000.
- Поточний Free-план дозволяє том до 500 МБ та вимагає sleepApplication=true.
  Перший запит після сну може потребувати додаткового часу на пробудження.
- Нові інсталяції реєструються через API. CLI залишається для персональних токенів і відкликання.
- Налаштуйте HTTPS domain. Перевірте `/healthz`, захищений пошук і збереження
  квоти після перезапуску. Журнали INFO у stdout містять JSON-події `server_started`, `client_connected`
  та `request_completed`: request/session ID, мітку токена, операцію, шаблон маршруту,
  статус, тривалість, кількість результатів і upstream-запитів. Адреси, координати,
  IP, Authorization, хеші й upstream URL не журналюються.
- `X-UAAS-Session-ID` — необов’язковий UUID сесії плагіна. Окремого HTTP-підключення
  або телеметрії кешу немає: повтори в локальному кеші не потрапляють у Railway Logs.
- Перед оновленням зробіть backup тому; rollback — попередній commit/image
  із тим самим томом. 0.1.0.4 ідемпотентно додає таблиці installations/registrations,
  не змінюючи чинних токенів і лічильників; попередній сервер ігнорує нові таблиці.

**Порядок оновлення 0.1.0.4:** спочатку розгорнути сервер із реєстрацією та квотою
у відповідях, потім розповсюджувати плагін. Сервер оновлено 2026-11-12 до commit c300640,
deployment `90a3dd23-6e36-432d-917a-9ce873eebbdd` — SUCCESS. Автоматична реєстрація,
квота у відповідях і реальний пошук із установленого QGIS перевірені;
старі персональні токени та їхні лічильники збережені.

Сервер розгорнуто 2026-11-12: https://uaaddresssearch-production.up.railway.app.
Стан перевірок та особливості запуску — у `research/deployment.md`.
Тестовий тариф Visicom має
1500 запитів/добу й термін 30 днів. Закритий пілот із токенами потребує
відповідного режиму використання API; MIT не змінює умов провайдера.
Офіційні джерела: [API](https://api.visicom.ua/uk/products/data-api),
[тарифи](https://api.visicom.ua/uk/price),
[умови публічного доступу](https://api.visicom.ua/uk/docs/terms-of-free-use),
[Railway Volumes](https://docs.railway.com/volumes/reference).

## Розробка, тести та випуск

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests/unit -v
.\.venv\Scripts\python.exe -B -m unittest discover -s tests/server -v
.\.venv\Scripts\ruff.exe check .
python -B scripts/smoke_test_all_qgis.py
python -B scripts/package_plugin.py
python -B scripts/sync_to_profiles.py
python -B scripts/smoke_test_all_qgis.py --installed
```

Unit/API-тести синтетичні, QGIS-тести використовують локальний HTTP-сервер.
Smoke runner знаходить підтримувані QGIS у Program Files; налаштування й auth DB
кожного запуску ізольовані. Він перевіряє джерело та, з `--installed`, кожну
встановлену копію; звіти — `artifacts/`. Це не автоматизація видимого вікна QGIS.

Синхронізація охоплює наявні профілі QGIS3/QGIS4, використовує staging/rollback,
перевіряє SHA-256 кожного файла й відмовляє при запущеному QGIS. Явний виняток:
`python -B scripts/sync_to_profiles.py --allow-running-qgis`; після нього
перезапустіть QGIS або перезавантажте плагін.

Живий API перевіряється лише явно, максимум трьома запитами:

```powershell
.\.venv\Scripts\python.exe -B scripts/live_check.py --env-file .env --max-requests 3
```

Ця діагностика звертається прямо до Visicom і не входить у квоту проксі.
ZIP відтворюваний, містить лише runtime-файли та MIT; локальний `plugins.xml`
має відносний download URL, який потрібно замінити адресою хостингу при публікації.
Версія береться з metadata.txt; публічне розміщення й заповнення контактів автора
в метаданих є окремим етапом.
