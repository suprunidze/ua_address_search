# Перевірка 0.1.0.4 — 2026-11-12

- 14 unit-тестів: моделі, LRU/single-flight, скасування, монотонні знімки квоти,
  атомарний локальний лічильник, ізоляція ключів/діб, перезапуск і перевищення без блокування.
- 20 серверних тестів успішні у Python 3.13 і 3.12: реєстрація, конкурентні повтори,
  глобальні ліміти нових інсталяцій, відкликання, квота у відповідях і помилках,
  збереження токенів/лічильників та перевизначення 1000, безпечні INFO-журнали.
- 17 QGIS integration-тестів у кожному з 12 запусків source/installed — PASS:
  QGIS 3.28.2, 3.34.10, 3.40.8 (каталог 3.40.4), 4.0.2; джерело та профілі
  1545/default відповідного покоління QGIS. Загалом 204 QGIS-перевірки.
- Перевірено обидва режими, міграцію старого доступу, автоматичну реєстрацію,
  прямі запити без Railway, спільний кеш, актуалізацію квоти без окремих HTTP,
  чекбокс геометрії, його перемикання, flash, stale replies, копіювання та іконки.
- Відтворене зависання blockingGet при скасуванні до створення reply усунуто
  транспортом через QgsNetworkAccessManager + Qt event loop, queued abort і deadline.
  Додано окремий тест цієї гонки та тайм-ауту; очищення задач перевірене в усій матриці.
- Тест повтору під час завантаження геометрії використовує явний бар’єр готовності
  HTTP-сервера замість залежності від затримки. Фінальна матриця повністю успішна.
- Два релізні тести: точна відповідність 16 runtime-файлів ZIP, MIT, версії metadata/XML,
  відсутність секретів і кешів. SHA-256 архіву:
  4cdc36567493e32fda7a591b510a1a640c24f6ca2811e111c47533ea5b0f3aa2.
- Установлені копії QGIS3/1545, QGIS3/default, QGIS4/1545, QGIS4/default відповідають
  ZIP за SHA-256. Для відкритого QGIS потрібне перезавантаження плагіна або перезапуск.
- Візуально перевірено компактну панель та обидва режими налаштувань у Qt6;
  offscreen-знімки з системним Segoe UI збережені лише в artifacts/.
- Ruff і git diff --check — PASS. Звіти: artifacts/qgis_smoke.json,
  artifacts/qgis-run-*.log, artifacts/profile_sync.json, artifacts/server-tests-py312-004.txt.
- Нові перевірки використовували синтетичні дані й локальний HTTP-сервер;
  Visicom не викликався. Railway, GitHub і production-квоти на цьому етапі не змінені.
- Перед розповсюдженням потрібне окреме оновлення сервера: нова реєстрація та метадані
  квоти не працюють зі старим сервером. Чинні персональні токени сумісні.

## Попередня перевірка 0.1.0.2 — 2026-11-12

- Unit-моделі: 6 тестів; сервер: 14 тестів, включно з CLI токенів.
- API, адаптер і квоти перевірені в Python 3.13 та Python 3.12; CLI додатково
  перевірений у Python 3.13. Залежності зафіксовані, pip check успішний.
- QGIS 3.28.2, 3.34.10, 3.40.4 та 4.0.2: по 6 інтеграційних тестів
  джерела й кожної встановленої копії — 12 успішних запусків, 72 перевірки.
- Установлені профілі: QGIS3/1545, QGIS3/default, QGIS4/1545, QGIS4/default;
  SHA-256 усіх установлених runtime-файлів відповідає ZIP.
- Перевірено реальний threaded QgsLocator, скасування, редиректи, Auth Manager,
  CRS 4326/3857/32636, геометрію та повторне initGui/unload без дублікатів.
- Два релізні тести: MIT, склад ZIP, відповідність джерелам і версій XML.
- Live Visicom: forward, reverse, feature; додатково повний локальний сценарій
  QGIS → FastAPI → Visicom → карта й резерв квоти. На реалізаційні live-перевірки
  використано 4 запити; попереднє дослідження використало ще 2.
- Візуально перевірено українську панель у Qt6, локальний знімок у artifacts/.
- Ruff і git diff --check успішні; .env і тестові секрети не входять у Git/ZIP.

Артефакти запуску: artifacts/qgis_smoke.json, artifacts/profile_sync.json.
На початковому локальному етапі Docker був недоступний. Подальший Docker build
і production deployment Railway успішні; авторизовані live-перевірки й збереження
квоти після перезапуску описані у research/deployment.md. Фактичний тариф/строк
ключа та зовнішні витрати за тим самим ключем сервер не може визначити.

Відхилення від плану: префікс Locator — uas, оскільки QGIS ігнорує префікси
сторонніх плагінів коротші за три символи. Функціональність збережена.
